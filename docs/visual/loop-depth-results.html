Looped transformers · arithmetic · 23 Nov 2026

Do loops add reasoning depth?

Loops buy steps. Weights buy number size. Longer numbers are broken.

Tiny transformers learn nested arithmetic like (8-3)*(4-6)+7=-3. We compare a small model, the same model run 8 times in a row, and a model with 8× more layers. New here? The setup section explains every term.

Setup

What this project tests

The question

A transformer normally passes its input through a stack of distinct layers once. A looped transformer runs the same few layers several times in a row. It can think longer without more weights.

Does that extra thinking let it solve problems with more steps? And can a small looped model do what a much bigger one does?

The task

Tiny models are trained from scratch to answer problems like these:

7*8=56 (8-3)*(4-6)+7=-3 352+47=399

Arithmetic lets us set difficulty exactly and check every answer. Two dials set the difficulty.

  • Depth: steps that must happen in sequence (examples below).
  • Number size: digits in the inputs and the answer. 9071+6268 is one step but needs careful carrying.

Keeping the two apart tells us which one loops help with.

What depth looks like

Depth counts steps that wait for each other, not operators. Independent operations share a step.

(8-3)*(4-6)+7 step 1 8-3 = 5 and 4-6 = -2 independent, same step step 2 5 * -2 = -10 needs both step 3 -10 + 7 = -3 needs step 2 depth 3, 4 operators
7*7-4*6 = 25 depth 2 both multiplications at once, then subtract 6+5+2+9 = 22 depth 3 each addition waits for the one before

How the model reads a problem

One character is one token. The vocabulary has 46 tokens: the digits, + - * ( ) =, a stop sign # after each answer, and a few letters saved for later tasks. So 352 is three tokens. There are no word pieces as in chat models.

The model writes the answer one token at a time, reading only what came before.

The three models

Each has an input layer, a core and an output layer. Only the core changes.

Looped and shallow have the same weights. Looped and deep do the same amount of work per answer. So looped vs shallow asks "does repeating help?" and looped vs deep asks "is repeating as good as more layers?".

Place-value tags

The token 3 looks the same in 3, 30 and 300. Place-value tags add a label to each digit for its place, counted from the right: ones = 1, tens = 2, hundreds = 3. Answer digits are labelled by their position in the answer.

335221+4271=319293

Why: column addition lines up ones with ones and tens with tens, so the labels should make big numbers easier. The idea comes from McLeish et al. (NeurIPS 2024).

Answer order

Normally the answer comes biggest digit first: 352+47=399. Reversed, it comes smallest digit first: =993. We flip it back to score it.

Why: carries move from the ones column up. Biggest-first forces the model to know every carry before writing anything. Lee et al. (ICLR 2024) found reversed order helps small models add.

How we judge results

  • Accuracy is the share of test problems answered exactly right. Each test group has about 1,000 problems, so differences under 0.03 can be chance.
  • Every model is trained twice from different random starts, for 120k steps. Numbers below are the average of the two. Where the two disagree, both are shown.
  • Before each experiment we wrote down what result would count as a yes.
  • Gap closed is how much of the shallow-to-deep difference the looped model makes up. 1.0 means as good as deep. 0 means no help.

What we know so far

Loops buy steps. The looped model beats shallow by more as problems get deeper, and matches deep with a quarter of the weights.

Holds

Finding 1 · steps

Loops keep up with depth as problems get longer

What

Accuracy by depth, on problems with 1-digit answers so number size isn't a factor.

Why

If loops add steps, looped should pull away from shallow as depth grows and keep up with deep.

Result

Line = average of the two runs, band = their range. Grey = depths seen in training. Hover for each run.

Looped beats shallow by +0.11 at depth 4 and +0.25 at depth 8. It stays within 0.03 of deep everywhere, including depth 13.

Meaning

Repeating the same layers buys about as many steps as four times the weights.

Finding 2 · number size

Bigger answers need more weights, not more loops

What

Accuracy at depths 3–6, split by how many digits the answer has.

Why

If big numbers need stored knowledge, extra distinct layers should beat extra passes.

Result

Bar = average of the two runs, thin line = their range.

Loops do the whole job on steps and part of it on numbers. Saunshi et al. (ICLR 2025) saw the same split in language models: loops helped reasoning far more than memory.

Finding 4 · longer numbers

Place-value tags break on numbers longer than training

What

Training never had 4-digit inputs. Every model got 0% exactly right on them, even a single a+b. We asked 300 random 4-digit sums like 6268+9071 to see how close the models came.

Why

Near misses and nonsense call for different fixes.

Without tags the models estimate well. With tags the answers are nonsense. Yet tags help a lot on trained sizes: 3-digit sums go from 0.24 to 0.74 exact.

The no-tag models had 40k training steps, the tagged ones 120k.

Meaning

Question digits only ever had labels 1–3. Label 4 only appeared on the 4th answer digit. So a thousands digit arrives labelled as an answer position. This is a likely cause, not yet tested.

Finding 5 · answer order

Reversed answers pay off only in the bigger model

What

The three models trained again with reversed answers.

Why

Reversed order follows the carries, so it should make big answers easier. We'd switch if it gained at least 0.05 on multi-digit inputs at a cost of no more than 0.03 elsewhere.

Result

Reversed minus normal. Two bars per model, one per run. Blue = reversed better.

Reversed hurts shallow, is about neutral for looped and helps deep. It missed the bar on all three, so normal order stays.

Meaning

Reversed order seems to need spare capacity. It may matter again for wider models.

Finding 6 · operator type

Multiplication isn't harder once size is fixed

What

Problems with many * against problems with few, at the same depth, answer size and input size.

Why

If multiplication itself were hard, *-heavy problems would fail more at equal size.

Result

The two score within 0.015 of each other for every model. Unmatched, *-heavy problems look much harder (looped 0.50 → 0.19), but only because their answers are bigger.

Meaning

Difficulty comes from depth and number size, not operator type.

How far to trust this

  • Two runs per model. They agree within 0.01–0.04 on most results and differ by up to 0.10 on 3-digit answers.
  • No test problem appears in training, except where noted.
  • The models are tiny (256 wide) and still improving. Deep's edge on numbers may shrink with width or more training.

What's next

The goal is a recipe that mostly works for arithmetic, then wider models toward middle-school math.
