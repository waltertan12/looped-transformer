Looped transformers · PEMDAS arithmetic · as of 23 Nov 2026

Do loops add reasoning depth?

Tiny transformers trained from scratch on nested arithmetic like (8-3)*(4-6)+7=-3. Same weights run several times (looped) versus no repeats (shallow) versus more distinct layers (deep). 34 training runs and 28 scoring runs so far; the headline numbers below are 120k-step models on two seeds. If you're new, the first section explains every term used later.

What this project is testing

The question

A transformer normally passes its input through a stack of distinct layers once. A looped transformer reuses the same few layers several times in a row, so it can "think longer" without having more weights. The question: does that extra thinking let it solve problems that need more steps, and can a small looped model do what a much bigger one does?

The test bed: nested arithmetic

Tiny models are trained from scratch to answer problems like these, one character at a time:

7*8=56 (8-3)*(4-6)+7=-3 352+47=399

Arithmetic is useful because we control difficulty exactly and every answer can be checked. Two dials matter:

  • Depth (number of steps): how many operations must happen in sequence. (8-3)*(4-6)+7 has depth 3: work out both brackets, multiply, then add. More depth means more sequential reasoning.
  • Number size: how many digits the inputs and the answer have. 9071+6268 is one step but needs careful digit work and carrying.

Separating the two dials is what lets us say which one loops help with.

The three models

Every model has an input layer, a "core" and an output layer. Only the core changes:

Looped and shallow have identical weights; looped and deep do the same amount of computation. So looped vs shallow isolates "does repeating help?", and looped vs deep isolates "is repeating as good as having more distinct layers?".

Place-value tags

The model sees each digit as a separate token, but on its own a token doesn't say whether a 3 means three, thirty or three hundred. Place-value tags attach a small label to every digit saying which place it is in: ones = 1, tens = 2, hundreds = 3, counted from the right of each number. Answer digits are labelled by position in the answer instead. The idea comes from McLeish et al. (NeurIPS 2024), who called them "Abacus embeddings".

335221+4271=319293

Why test it: lining up ones with ones and tens with tens is exactly what column addition needs, so tags should make big-number arithmetic easier.

Answer order: normal vs reversed

Normally the model writes 352+47=399 left to right, biggest digit first. In reversed order it writes the answer smallest digit first: 352+47=993, which we flip back when scoring.

Why test it: people add from the ones column up, because carries move leftward. Writing the biggest digit first forces the model to know every carry before it writes anything. Reversed order lets it write digits in the order it can work them out. Earlier work (Lee et al., ICLR 2024) found this helps small models with addition.

How we judge results

  • Accuracy = share of test problems answered exactly right. Each test group holds about 1,000 problems, so a difference under about 0.03 can be chance.
  • Seeds: each model is trained twice from different random starts. Results shown as "0.86 / 0.87" are seed 0 / seed 1. A result counts only if both agree.
  • Rules written in advance: before each experiment we wrote down what result would count as a yes, so we can't move the goalposts after seeing the numbers.
  • %Gap = how much of the shallow-to-deep gap the looped model closes. 1.0 means looped is as good as deep; 0 means looping added nothing.

What we learned, and what we didn't

Learned

Loops buy steps. On problems with many sequential steps, looped beats shallow (same weights) by +0.11 at 4 steps and +0.25 at 8 steps.

Both seeds, 120k steps. The gap grows with step count.

Learned

Looped matches deep on steps with a quarter of the weights. Within ±0.03 at every depth.

4.4M looped vs 19M deep, same compute. Holds past the training depth (depth 13, trained ≤ 8).

Learned

Weights buy number size. Deep beats looped by +0.05 to +0.15 on big answers and big inputs, and by the same amount on pure addition and subtraction.

So it is not about multiplication tables. H13 rejected on unseen problems.

Learned

Operator mix doesn't matter once depth and number size are fixed (±0.015).

H14 not supported. Multiplication-heavy problems are hard only because their answers are big.

Learned

Training length mattered a lot. 40k → 120k steps lifted everything by +0.08 to +0.26, and models are still not converged.

The loop gap survived the longer training: it is capability, not faster learning.

Broken

No generalization to longer numbers. Every model scores 0% on 4-digit inputs, even a single a+b.

The place-value tags cause the collapse: without tags, answers stay within 5% (0.92); with tags, garbage (0.01–0.10).

Broken

A model trained at 8 loops only works at 8 loops (≤ 0.11 at other counts).

Blocks "use fewer loops on easy problems" until training changes (plan step 5).

Depends

Reversed answer order hurts small models and helps big ones: big answers −0.08 shallow, −0.03 looped, +0.12 deep.

Fails the pre-set rule on all three, so normal order stays.

Unknown

Why number size needs weights, whether width fixes it, and whether a model can choose its own loop count.

These are the roadmap below.

Finding 1 · steps

Loops close the gap to depth as problems get longer

What

Accuracy by depth on problems whose answer is a single digit, so number size can't be the difficulty. Models trained on depths 1–8, tested on 2–13.

Why

If looping adds sequential reasoning, the looped model should pull away from shallow as depth grows and keep up with deep, even past the depths it trained on.

Result

Lines = mean of the two seeds; shaded band spans them. Grey area = depths seen in training.

Looped beats shallow by +0.11 at depth 4 and +0.25 at depth 8, and stays within ±0.03 of deep everywhere, including depth 13.

Meaning

The core claim holds: repeating the same layers buys the ability to do more steps, about as well as four times the weights.

Finding 2 · number size

Bigger answers need more weights, not more loops

What

Accuracy at depths 3–6 split by how many digits the answer has.

Why

If loops were a general boost, looped would match deep on big numbers too. If big numbers need stored knowledge (digit facts, carrying patterns), extra distinct weights should win there.

Result

Bar = mean of the two seeds; the thin line spans them.

Meaning

Loops do most of the job on steps and only part of it on number size. This mirrors Saunshi et al. (ICLR 2025): in their language models, loops closed 34–48% of the gap on memorization but over 100% on reasoning.

Finding 3 · pure addition and subtraction (H13)

Deep's edge on numbers doesn't come from multiplication

What

New test-only sets with only + or only -, inputs of exactly 1–4 digits, scored on the already-trained models. Shown: problems never seen in training, depths 1–3, 2–3-digit inputs.

Why

Finding 2 could mean deep wins because multiplication needs memorized tables (a lookup job). Addition has no tables, just a step-by-step carrying procedure, which should suit loops. If deep's edge disappears without *, the gap was about lookup; if it stays, it's about number size itself.

Finding 4 · longer numbers (broken)

Place-value tags break on numbers longer than training

What

Training data never contained 4-digit inputs. We asked each model 300 random 4-digit additions such as 6268+9071 and compared models trained with and without place-value tags.

Why

Every model scored 0% exact on 4-digit inputs in the add/sub sets, even for a single a+b. We wanted to know whether the models were close or lost.

Without tags the models estimate well: right size, right leading digits, wrong last digits. With tags the answers are nonsense. Yet on number sizes seen in training, tags help a lot (3-digit sums: 0.24 → 0.74 exact).

Meaning

The tags are labels the model has only seen with values 1–3 on question digits. One table of labels is shared by question and answer, so a thousands digit arrives with label 4, which until now only ever meant "4th digit of the answer". Likely the model reads it as an answer position. This is a known weakness of fixed position labels; it is not yet confirmed by an experiment.

Finding 5 · answer order

Reversed answers pay off only with enough weights

What

The same three models trained with reversed answers (smallest digit first), two seeds, 120k steps, compared with normal order.

Why

Reversed order matches how carries flow, so it should make multi-digit answers easier (Lee et al. 2024). The rule set in advance: switch if reversed gains ≥ 0.05 on multi-digit inputs and costs ≤ 0.03 on 1-digit inputs.

Result

Reversed − normal accuracy; the two bars per model are seeds 0 and 1. Blue = reversed better, red = worse.

Reversed hurts shallow, is roughly neutral for looped and helps deep, especially on big answers (+0.13 / +0.10). It failed the rule on all three models, so normal order stays the default.

Meaning

Reversed order is not a free win. It seems to need spare capacity to pay off, so it may matter again for wider models.

Finding 6 · things that didn't matter

Operator mix, and tags on the smallest model

What

(a) Whether problems with more * are harder, comparing only problems with the same depth, answer size and input size (H14). (b) Tags on the shallow model.

Why

(a) If multiplication itself were hard, *-heavy problems should fail more even at equal size. (b) Tags should help any model if they help at all.

Result

(a) The most-* third scores within ±0.015 of the least-* third, all models, both seeds. Unmatched, *-heavy problems look much harder (looped 0.50 → 0.19), but that is entirely their bigger answers. (b) Tags changed shallow by −0.01; on looped they added +0.055 on big answers.

Meaning

Difficulty comes from depth and number size, not operator type. Tags need some capacity to be useful, and Finding 4 shows they also have a cost.

How far to trust this

  • Two seeds per model at 120k steps. Seeds agree within 0.01–0.04 on most slices but differ by up to 0.10 on 3-digit answers.
  • Test sets hold about 1,000 problems per cell (±0.03 sampling noise); no test problem appears in training for the main data.
  • Models are tiny (256 wide) and still improving at 120k steps; "deep beats looped on numbers" could shrink with width or training.
  • Two pre-set rules measured the wrong thing (D-011 used 1-digit inputs; H13 averaged in 0% cells). Both were caught and logged; conclusions rest on the corrected views.

Roadmap

Goal: know "what mostly works" for arithmetic, then go wider (H16) toward middle-school math. Each stage has its decision rule written before it runs.

Next

Fix longer numbers (H18)

  • Train looped and deep with a random offset on the tags, and with separate question/answer tag tables; add a no-tag 120k control.
  • Test on 4–5-digit inputs. Success: 4-digit a+b above 0.5 exact without losing in-range accuracy.
  • Cheap first: plot what each attention head looks at per loop pass on saved models (free).
Then

Variable loop count (H9, plan step 5)

  • Train with an answer read out after every pass (deep supervision or progressive loss), so any loop count works.
  • Then let the model stop early: confidence rule, then a learned stop head. Success: few loops on easy problems, many on hard ones, no accuracy loss. Neither paper did this.
Then

Settle the recipe

  • Full grid with the fixed recipe, 2 seeds, longer training. Fit accuracy against log(depth) for loops vs layers.
  • Prefix attention (H15) and loop placement (H11) as ablations.
Later

Wider models and harder math

  • H16: width 512–1024. Does width fix number size, and do loops still add steps on top?
  • H12 chain task (data exists), H17 algebra (3*x+5=20;x?), then back to Qwen if a recipe clearly works.
