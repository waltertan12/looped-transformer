# H13 / H14 Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Score the 12 saved D-012 checkpoints on new add-only / sub-only test sets (H13) and slice existing results by operator mix (H14), with pre-registered rules and a report.

**Architecture:** A small generator module for single-operator expressions; a test-only build script writing the existing frozen format; a checkpoint scorer reusing `FrozenData` + `dump_per_example`; label-join and report scripts reading `per_example.npz`.

**Tech Stack:** Python 3.12, numpy, torch (repo venv `.venv/bin/python`), pytest.

**Spec:** `docs/looped-math/plans/specs/2026-11-23-h13-h14-eval-design.md`

## Global Constraints
- No training and no change to `data/nested_bal` or to existing generators' RNG use (existing data must rebuild bit-identically).
- Frozen format: `<root>/test/<level:02d>.tokens.npy` (uint8, width 80) + `.meta.npy` (int64); `meta.json` with `vocab`, `width`, `columns`, `level_column: "depth"`, `bound: null`, `eos: "#"`, `seed`, `slices`.
- Inputs **exactly** k digits, k ∈ {1,2,3,4}; ~1000 rows per (depth, k) cell; full row (prompt + answer + `#`) ≤ 80 chars.
- Score each run at its training K (`args["train_loops"]`, a single integer for all D-012 runs) and respect `args["reverse_answer"]`.
- Rules (verbatim from spec): H13 supported if deep − looped ≤ 0.03 on add and sub (averaged over 2–4-digit inputs, both seeds); rejected if ≥ 0.05. H14 supported if, within cells matched on depth, answer digits and input digits, accuracy falls ≥ 0.05 from the lowest to the highest `mul_frac` third (both seeds).
- At most 2 GPU jobs at a time, `torch.cuda.set_per_process_memory_fraction(0.4)`.

## Review Focus
- Cells that can't reach 1000 distinct prompts (1-digit add at depth 1 has 81): build must keep what exists, record the count in meta, never loop forever. → Task 2 test.
- Reversed-answer checkpoints scored with normal answers would read ~0: scorer must pass `reverse_answer` from the checkpoint args. → Task 3 test.
- Row-order mismatch between `per_example.npz` and test tokens (silently wrong H14 labels): join must assert `answer` and `depth` agree. → Task 4 test.
- Leading `-` in the answer is not an operator; counting must use the prompt only (`length` columns). → Task 4 test.
- H14 cells with too few rows give noisy thirds: skip cells with < 60 rows and report how many rows were used. → Task 5 test.
